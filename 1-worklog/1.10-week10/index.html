Exercise 2: Deploying Applications on EKS — Configuring kubectl, Pods, Deployments & Self-Healing

With the Kubernetes cluster online and operational, deployed a real-world web application using the industry-standard kubectl CLI tool:

1. Connecting kubectl to EKS Cluster: In AWS CloudShell, generated the necessary local authentication credentials in kubeconfig to communicate with the EKS Control Plane:

aws eks update-kubeconfig --region us-east-1 --name LabT2-EKS-Cluster

2. Authoring Manifest and Deploying Pods with LoadBalancer Service: Created manifest file nginx-deployment.yaml declaring an NGINX web application deployment with 2 replicas and a LoadBalancer service:

apiVersion: apps/v1
kind: Deployment
metadata:
  name: web-test-deployment
spec:
  replicas: 2
  selector:
    matchLabels:
      app: web-test
  template:
    metadata:
      labels:
        app: web-test
    spec:
      containers:
      - name: nginx
        image: nginx:latest
        ports:
        - containerPort: 80
---
apiVersion: v1
kind: Service
metadata:
  name: web-test-service
spec:
  type: LoadBalancer
  selector:
    app: web-test
  ports:
    - protocol: TCP
      port: 80
      targetPort: 80

Applied the manifest configuration to the cluster:

kubectl apply -f nginx-deployment.yaml

Exercise 4: AWS CodeBuild — Automated Build Server & Docker Image Packaging

AWS CodeBuild is a fully managed continuous integration service that compiles source code, executes automated unit tests, and produces deployable software packages without provisioning build servers:

1. Authoring the Build Specification (buildspec.yml): The buildspec.yml file serves as the instruction blueprint guiding CodeBuild through the build phases: authenticating to Amazon ECR, compiling the Docker image, and exporting deployment descriptors:

version: 0.2

phases:
  pre_build:
    commands:
      - echo Logging in to Amazon ECR...
      - aws --version
      - aws ecr get-login-password --region $AWS_DEFAULT_REGION | docker login --username AWS --password-stdin $AWS_ACCOUNT_ID.dkr.ecr.$AWS_DEFAULT_REGION.amazonaws.com
      - REPOSITORY_URI=$AWS_ACCOUNT_ID.dkr.ecr.$AWS_DEFAULT_REGION.amazonaws.com/$IMAGE_REPO_NAME
      - COMMIT_HASH=$(echo $CODEBUILD_RESOLVED_SOURCE_VERSION | cut -c 1-7)
      - IMAGE_TAG=${COMMIT_HASH:=latest}
  build:
    commands:
      - echo Build started on `date`
      - echo Building the Docker image...
      - docker build -t $REPOSITORY_URI:latest .
      - docker tag $REPOSITORY_URI:latest $REPOSITORY_URI:$IMAGE_TAG
  post_build:
    commands:
      - echo Build completed on `date`
      - echo Pushing the Docker image...
      - docker push $REPOSITORY_URI:latest
      - docker push $REPOSITORY_URI:$IMAGE_TAG
      - echo Writing image definitions file...
      - printf '[{"name":"%s","imageUri":"%s"}]' $IMAGE_REPO_NAME $REPOSITORY_URI:$IMAGE_TAG > imagedefinitions.json
artifacts:
  files: imagedefinitions.json

2. Pushing Files to CodeCommit and Triggering the Build: Committed buildspec.yml, Dockerfile, and index.html to repository LabT5-app-repo. Triggered the build project via the AWS CLI:

git commit -m "Fix image name typo in docker build command"
git push origin main
aws codebuild start-build --project-name LabT5-Docker-Build --region us-east-1
